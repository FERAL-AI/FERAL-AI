## Product boundary and proposed defaults

Proposed, not approved: one personal agent identity and durable conversational record across phone and desktop; phone remains the native sensor/audio/control surface; desktop or an explicitly chosen hosted brain performs general orchestration. Keep provider choice, recording consent, health sharing, purchase approvals and disconnected behavior visible. The phone must remain useful while a home computer sleeps, but offline capture is different from offline autonomous reasoning.

Do not silently choose minimum iOS version, cloud hosting, agent name, mandatory Supabase account, relay operator, unlimited recording, physiological personalization, or payment provider. Those need product decisions. Existing iOS deployment is iOS 16; newer Apple APIs need availability gates or an approved minimum-version change.

## Platform constraints, with primary sources

- BLE background support allows bounded event handling, not indefinite application execution. State restoration must be configured on the actual central manager. [Core Bluetooth background guide](https://developer.apple.com/library/archive/documentation/NetworkingInternetWeb/Conceptual/CoreBluetooth_concepts/CoreBluetoothBackgroundProcessingForIOSApps/PerformingTasksWhileYourAppIsInTheBackground.html). The JWBle vendor owns that manager, so declaring a mode alone cannot add restoration.
- Force quitting prevents Bluetooth restoration relaunch; system memory eviction differs. [TN3115](https://developer.apple.com/documentation/technotes/tn3115-bluetooth-state-restoration-app-relaunch-rules).
- iOS 26 adds documented Core Bluetooth foreground-like privileges during an existing Live Activity; this is an optional version-gated opportunity, not proof that this app already works indefinitely. [Current Core Bluetooth overview](https://developer.apple.com/documentation/corebluetooth).
- Scheduled refresh/processing and silent pushes are system controlled. A refresh task is not a guaranteed 15-minute heartbeat; push is not an always-on WebSocket substitute. [Choosing background strategies](https://developer.apple.com/documentation/BackgroundTasks/choosing-background-strategies-for-your-app).
- SpeechAnalyzer/SpeechTranscriber supports on-device long-form transcription, with hardware/language restrictions and downloadable assets. Preflight model installation; offline inference still needs installed assets. [Apple WWDC25 SpeechAnalyzer session](https://developer.apple.com/videos/play/wwdc2025/277/).
- App Intents exposes an app's declared actions to Siri/Shortcuts/system surfaces; it is not unrestricted control of other apps. Confirmation is supported. [AppIntent](https://developer.apple.com/documentation/AppIntents/AppIntent), [requestConfirmation](https://developer.apple.com/documentation/AppIntents/AppIntent/requestConfirmation(conditions:actionName:dialog:)).
- Notification actions can require device unlock. [authenticationRequired](https://developer.apple.com/documentation/usernotifications/unnotificationactionoptions/authenticationrequired).
- Apple Pay uses system payment authorization; agent intent and payment authorization are separate stages. [PKPaymentAuthorizationController](https://developer.apple.com/documentation/passkit/pkpaymentauthorizationcontroller), [Apple payment authorization event](https://developer.apple.com/documentation/applepayontheweb/applepaysession/onpaymentauthorized).
- App Review requires explicit permission for sharing personal data with third-party AI. Health data has restrictions on advertising/data mining, inaccurate HealthKit writes and iCloud storage. Physical goods use non-IAP payment; digital functionality generally uses IAP subject to current storefront exceptions. Apple Pay needs purchase disclosures. Review also addresses account deletion and medical-accuracy claims. [App Review Guidelines, 1.4.1, 3.1, 4.9, 5.1](https://developer.apple.com/app-store/review/guidelines/). Assess submitted claims and actual flows against the live rules before release.
