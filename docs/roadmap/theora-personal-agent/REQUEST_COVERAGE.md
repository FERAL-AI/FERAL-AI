## Missing explicit research deliverable

The requested Instinct-style report is still a distinct deliverable: a short verdict for each of iMessage bridge, stripe/link-cli, Browser Use versus Playwright, existing glasses trigger, and exact FERAL module integration. Each verdict must separate actual confirmation/testing from docs-only reading, list blockers and risks, then give a stepwise implementation plan and a 60-second cafe acceptance scenario. General payment protocol research does not answer Link for Agents eligibility. Existing CDP/Playwright source is evidence to compare, not proof of real-account automation.

The original research request said to stop after the report and wait for go. Later authorization to build the full app does not create payment credentials, authorize external messages or waive real-account tests; make the research findings reviewable before enabling those new external effects.

1. **Close the current release blockers.** Finish the complete post-correction backend run and required CI; archive candidate/source identity and actual 9.26 startup evidence. Re-run populated-profile setup/chat/approval/cancel/quit/relaunch and supported layout/accessibility checks. Add disk/resource preflight so a failed build or unavailable model cannot masquerade as an app failure. This is a prerequisite for trusting the next feature.
2. **Establish owner, event and durable task boundaries.** Implement REL-01/02/04 with explicit owner/session/device identities, durable review/action outcomes, execution fencing and reconnect reconciliation. Add the messaging lifecycle contract here, then prove concurrent FERAL/coding sessions cannot mix responses, approvals or memory ownership. These contracts support iMessage, proactive work, voice, social sharing and payments.
3. **Complete one full everyday workflow across desktop and iOS.** Build REL-03/05/06: grounded conversation and memory continuity, task progress/action inbox, managed coding activity and interruption-safe voice while work continues. Deliver executable contracts and the concrete IOS-01 to IOS-04 handoff to the iOS agent. Complete the five-item Instinct research in parallel; then implement named messaging/account/commerce adapters behind the same task ledger rather than separate authority.

Avatar/catalog refinement, Linux packaging investigations and PMF research can proceed with distinct ownership in parallel. Social matching, Link checkout and arbitrary CLI observation remain explicit backlog items rather than implied capability. Production signing, real accounts, named merchants and physical device acceptance still require their own concrete access and evidence.
